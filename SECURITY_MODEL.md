# Security model
Server and Postgres own authority. Overlays are read-only; possession of their token must never authorize controls. Campaign authorization, current custody, version, expiry, evidence and receiving consent are revalidated in one transaction. Provider delivery identifiers are deduplicated. Webhooks require signature verification over the unmodified body and timestamp freshness. OAuth uses unpredictable state and expiring server-side sessions; credentials must never appear in logs or URLs beyond provider-required authorization redirects. See final review packet for verified versus pending controls.
